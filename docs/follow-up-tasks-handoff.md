## 业务目标

用户可以为职位申请记录下一步行动、截止时间和备注，从所有申请中查询
今天要做的事情以及已经逾期的事情，完成后也能重新打开。

## 验收标准

- 为已有申请创建任务，记录标题、备注、截止时间；新任务状态为 TODO。
- 查询详情，编辑内容，完成、取消、重新打开，以及删除任务。
- DONE 保存完成时间；重新打开或取消清除完成时间；重复设置同一状态不重复更新时间。
- 按申请、状态、截止时间范围、是否逾期筛选；分页并按截止时间和 id 稳定排序。
- 只有截止时间早于当前时刻的 TODO 任务算作逾期。
- 时间输入支持 UTC 偏移，响应统一 UTC；时间范围左闭右开。
- 更新、状态切换、删除校验任务独立版本，冲突返回 409。
- 不存在的任务或不属于指定申请的任务返回 404。
- 删除申请时数据库级联删除任务。
- V5 自动创建表、外键、状态约束和查询索引。
- 保持 DDD 分层：领域模型无 JPA 注解，仓储适配器处理持久化。

接口示例见 [后端 README](../backend/README.md#follow-up-tasks)。

## 边界与后续候选任务

本轮是任务记录和查询，没有邮件、推送或定时提醒。任务状态与申请状态独立，
不会自动把申请变成“已面试”，也不会因申请被拒绝而自动取消任务。
仍沿用单用户本地后端设计。

后续可按需要选择：

1. 面试安排与反馈：面试轮次、时间、联系人、结果及准备事项。
2. 工程交付：CI 自动测试、后端镜像、部署环境配置。
3. 多用户使用前的认证与数据隔离。
